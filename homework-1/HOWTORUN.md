# Як запустити Transactions API

Покрокова інструкція для запуску проєкту, тестів і прикладів запитів до кожного ендпойнта.

## 1. Вимоги

- Python 3.10+ (перевірити: `python3 --version`)
- `pip`
- Будь-який HTTP-клієнт для тестування запитів: `curl`, [Postman](https://www.postman.com/), або вбудована Swagger UI (див. нижче)

## 2. Встановлення

Відкрийте термінал у папці проєкту `transactions_api/` і виконайте:

```bash
cd transactions_api

# Створити віртуальне середовище
python3 -m venv venv

# Активувати його
source venv/bin/activate        # macOS / Linux
venv\Scripts\activate            # Windows (cmd/PowerShell)

# Встановити залежності
pip install -r requirements.txt
```

> Якщо `venv/` вже існує (наприклад, з попереднього запуску) — просто активуйте його, повторно створювати не потрібно.

### Швидкий старт через demo-скрипт

Кроки 2-3 можна виконати одним скриптом з папки `demo/` — він сам створить `venv`, встановить залежності й підніме сервер:

```bash
./demo/run.sh            # macOS / Linux, порт 8000
PORT=8080 ./demo/run.sh  # macOS / Linux, інший порт

demo\run.bat             # Windows, порт 8000
demo\run.bat 8080        # Windows, інший порт
```

## 3. Запуск сервера

```bash
uvicorn src.app:app --reload
```

- `--reload` автоматично перезапускає сервер при зміні коду (зручно під час розробки; для "продакшн"-подібного запуску цей прапорець можна прибрати).
- За замовчуванням сервер піднімається на `http://127.0.0.1:8000`.
- Щоб слухати на іншому порту: `uvicorn src.app:app --reload --port 8080`.

Зупинити сервер — `Ctrl+C` у тому ж терміналі.

### Інтерактивна документація

Поки сервер працює, відкрийте в браузері:

- **Swagger UI**: http://127.0.0.1:8000/docs — можна виконувати запити прямо з браузера.
- **ReDoc**: http://127.0.0.1:8000/redoc — альтернативний, більш "довідниковий" вигляд тієї ж документації.

## 4. Запуск тестів

В іншому терміналі (з активованим тим самим `venv`):

```bash
cd transactions_api
pytest -v
```

Корисні варіанти:

```bash
pytest -v tests/test_transactions.py   # лише один файл тестів
pytest -k "interest"                   # лише тести, де в назві є "interest"
pytest --tb=short                      # коротший вивід при падінні тесту
```

Сервер (`uvicorn`) для прогону тестів **не потрібен** — `pytest` піднімає застосунок в пам'яті через `TestClient`.

## 5. Швидка перевірка, що все працює

```bash
curl http://127.0.0.1:8000/
```

Очікувана відповідь:

```json
{"service": "Transactions API", "docs": "/docs"}
```

## 6. Приклади запитів до кожного ендпойнта

Нижче — мінімальний набір `curl`-команд, які можна виконати по черзі (сервер має бути запущений, див. крок 3). Дані зберігаються лише в пам'яті процесу — після перезапуску сервера все обнуляється.

### Створити транзакцію

```bash
curl -X POST http://127.0.0.1:8000/transactions \
  -H "Content-Type: application/json" \
  -d '{"toAccount": "ACC-00001", "amount": 100, "currency": "USD", "type": "deposit"}'
```

```bash
curl -X POST http://127.0.0.1:8000/transactions \
  -H "Content-Type: application/json" \
  -d '{"fromAccount": "ACC-00001", "toAccount": "ACC-00002", "amount": 25.50, "currency": "USD", "type": "transfer"}'
```

### Список транзакцій (з фільтрами та пагінацією)

```bash
curl http://127.0.0.1:8000/transactions

curl "http://127.0.0.1:8000/transactions?accountId=ACC-00001&type=transfer&from=2024-01-01&to=2024-12-31"

curl "http://127.0.0.1:8000/transactions?limit=20&offset=0"
```

Відповідь має вигляд `{"items": [...], "total": N, "limit": ..., "offset": ...}` — `items` це лише поточна сторінка, `total` — повна кількість з урахуванням фільтрів.

### Конкретна транзакція за id

```bash
curl http://127.0.0.1:8000/transactions/<id-з-попередньої-відповіді>
```

### Експорт у CSV

```bash
curl "http://127.0.0.1:8000/transactions/export?format=csv" -o transactions.csv
```

### Баланс рахунку

```bash
curl http://127.0.0.1:8000/accounts/ACC-00001/balance
```

### Зведення по рахунку

```bash
curl http://127.0.0.1:8000/accounts/ACC-00001/summary
```

### Прості відсотки на баланс

```bash
curl "http://127.0.0.1:8000/accounts/ACC-00001/interest?rate=0.05&days=30"
```

Детальний опис усіх параметрів, форматів відповідей і правил валідації — у [README.md](README.md).

### Запустити всі приклади одразу

Замість того, щоб виконувати команди з розділу вище по одній, можна прогнати готовий скрипт `demo/sample-requests.sh` — він засіє дані з `demo/sample-data.json`, викличе всі ендпойнти (включно з фільтрами, експортом і помилковими кейсами 400/404) і красиво виведе результат:

```bash
./demo/run.sh &                       # підняти сервер у фоні (один раз)
./demo/sample-requests.sh             # прогнати всі приклади запитів
BASE_URL=http://127.0.0.1:8080 ./demo/sample-requests.sh   # якщо сервер на іншому порту
```

## 7. Типові проблеми

**`ModuleNotFoundError: No module named 'fastapi'`**
Віртуальне середовище не активоване або залежності не встановлені — повторіть крок 2 (`source venv/bin/activate` і `pip install -r requirements.txt`).

**`Address already in use` при запуску `uvicorn`**
Порт 8000 зайнятий іншим процесом. Запустіть на іншому порту: `uvicorn src.app:app --reload --port 8001`, або зупиніть процес, що його займає.

**`400 Bad Request` при створенні транзакції**
Перевірте формат полів: `amount` > 0 і максимум 2 знаки після коми, `fromAccount`/`toAccount` у форматі `ACC-XXXXX`, `currency` — дійсний код ISO 4217, а набір полів відповідає `type` (`deposit` потребує `toAccount`, `withdrawal` — `fromAccount`, `transfer` — обидва). Тіло відповіді з `400` точно вкаже, яке поле і чому не пройшло валідацію. Зверніть увагу: тіло запиту не повинно містити зайвих/неочікуваних полів — вони теж відхиляються з `400`, а не ігноруються мовчки.

**`404 Not Found` на `/accounts/{id}/balance` чи `/summary`**
Рахунок ще жодного разу не фігурував у жодній транзакції — спочатку створіть транзакцію з цим `accountId`.

**`429 Too Many Requests`**
Перевищено ліміт 100 запитів/хвилину з одного IP. Зачекайте (підказку, скільки секунд, дивіться в заголовку `Retry-After` відповіді) і повторіть запит.

**Після перезапуску сервера всі дані зникли**
Це очікувана поведінка — сховище повністю в пам'яті, без бази даних і файлів на диску (за вимогами проєкту).
