# Prompt: docs/GENERAL_GUIDE.md — for a General Audience

**Run with:** Haiku 4.5 (`claude-haiku-4-5-20251001`)

---

You are explaining a software project to a **non-technical reader** — a
manager, a customer-support team lead, a stakeholder. No programming
knowledge. Write the document **in Ukrainian**.

## Facts about the system (everything you need; do not add technical detail beyond this)

- Це система для служби підтримки клієнтів: вона приймає звернення
  («заявки», «тікети») і допомагає команді підтримки їх обробляти.
- Заявки потрапляють у систему двома шляхами: по одній (наприклад, з
  веб-форми) або цілими файлами — списками заявок у трьох поширених
  форматах (таблиці CSV, файли JSON та XML).
- Під час завантаження система перевіряє кожну заявку: чи вказана коректна
  електронна адреса, чи не порожня тема, чи достатньо детальний опис. Якщо
  у файлі 50 заявок і 3 з них зіпсовані — 47 буде прийнято, а по кожній
  зіпсованій система пояснить, що саме не так.
- Система сама визначає тип звернення (проблема з доступом до акаунта,
  технічна несправність, питання про оплату, пропозиція покращення, звіт
  про помилку, інше) та терміновість (термінова / висока / середня /
  низька) — за ключовими словами у тексті звернення.
- До кожного автоматичного рішення система додає пояснення: які слова
  вона знайшла і наскільки вона впевнена (у відсотках).
- Людина завжди може виправити рішення системи вручну; кожна зміна —
  і автоматична, і ручна — зберігається в журналі, тож завжди видно, хто
  і чому змінив категорію чи пріоритет.
- Заявки можна шукати і фільтрувати: за статусом, терміновістю, категорією,
  виконавцем, тегами, текстом.
- Система ретельно протестована (56 автоматичних перевірок) і працює
  швидко: тисяча заявок імпортується за лічені секунди.

## Task

Write `docs/GENERAL_GUIDE.md` in Ukrainian, ~1 page, with:

1. **Що це за система** — 2–3 абзаци простою мовою; одна побутова аналогія
   (наприклад: «сортувальник пошти, який читає кожен лист, розкладає по
   поличках і позначає термінові»).
2. **Що вона вміє** — маркований список з 5–7 пунктів, кожен — вигода для
   команди підтримки, а не технічна функція.
3. **Як виглядає робота з нею** — короткий сценарій дня: завантажили файл
   зі зверненнями → система розсортувала і позначила термінові → команда
   почала з термінових → керівник бачить журнал рішень.
4. **Поширені запитання** — 3–4 питання: «Що буде, якщо у файлі помилки?»,
   «Чи може система помилитися з категорією?» (так, тому є ручне
   виправлення і журнал), «Чи можна довіряти автоматичним рішенням?»
   (система пояснює кожне рішення і показує впевненість).

## Rules

- Жодного технічного жаргону: без «API», «ендпоінт», «база даних»,
  «FastAPI», «валідація», «JSON» (формати файлів можна назвати «поширені
  формати таблиць і списків»).
- Короткі речення. Активний стан. Жодних розділів понад чотири зазначені.
- Не вигадуй можливостей, яких немає у списку фактів вище (наприклад,
  система НЕ відповідає клієнтам сама і НЕ інтегрується з поштою).
